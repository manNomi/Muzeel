# 연구 로드맵과 현재 증거 수준

## 현재 완료된 범위

- 원본 Muzeel의 프록시와 브라우저 탐색과 함수 제거 흐름을 코드로 확인했다.
- 최신 Selenium과 Chrome에서 막히는 호환성 문제를 최소 수정했다.
- Babel 기반 파서로 최신 JavaScript와 TypeScript와 Flow 구문을 처리했다.
- 파서 실패와 외부 스크립트와 보호 런타임을 원본으로 보존하는 정책을 만들었다.
- AI Agent의 행동 제안과 독립 정책 검증과 해시 연결 추적을 구현했다.
- Solid Connection 홈 화면 로컬 스냅샷에서 AI Agent 12행동을 실행했다.
- 독립 회귀 시나리오 다섯 개로 기능과 화면과 콘솔 오류를 비교했다.

## 아직 완료되지 않은 범위

- 원본 Muzeel 전체 실행 환경의 완전한 재현
- 행동 이후 새로 생성된 요소의 상태 그래프 수집
- 행동과 동적 JavaScript 청크 사이의 인과 연결
- 원본과 규칙 기반 재탐색과 AI Agent의 동일 예산 비교
- 로그인 성공과 실패 및 오류 복구 상태 실험
- 여러 사이트와 여러 내부 페이지의 반복 실험
- 실제 모바일 기기와 운영 환경의 장기 성능 검증

## 단계별 계획

### 1단계. 상태 전이 데이터 수집

브라우저 행동 전후의 상태 해시와 새 요소와 요청과 청크와 함수 실행 증가량을
기록한다. 공개 예시와 검증기는
[`experiments/state-aware-exploration`](../experiments/state-aware-exploration/README.md)에
둔다.

### 2단계. 규칙 기반 비교군 구현

새 상태에서 발견한 안전 요소를 DOM 순서로 실행하는 결정적 탐색기를 만든다.
같은 입력에서 같은 행동 순서가 나와야 한다.

### 3단계. AI Agent 비교

동일한 행동 횟수와 시간 예산과 허용 정책을 적용한다. 탐색 상태와 동적 청크와
함수 커버리지와 비용을 비교한다.

### 4단계. 상태 분기 실험

허가된 테스트 환경에서 로그인 성공과 실패 및 오류 복구를 독립 시나리오로
정의한다. 발생해야 하는 요청과 발생하면 안 되는 요청을 미리 기록한다.

### 5단계. 다중 사이트 재현

사이트 유형과 프레임워크와 인증 여부를 기준으로 대상을 선정한다. 한 사이트의
결과를 전체 웹으로 일반화하지 않는다.

## 참여하기 좋은 작업

- 상태 해시의 안정성 테스트
- Chrome DevTools Protocol 네트워크 이벤트 수집
- 동적 청크와 행동 전이 연결
- 규칙 기반 재탐색 비교군
- 로그인 테스트용 로컬 데모 사이트
- 공개 데이터 익명화 검사
- 반복 실험 통계와 시각화

구체적인 실험 제안과 데이터 추가 방법은 저장소의 이슈 템플릿과
[`CONTRIBUTING.md`](../CONTRIBUTING.md)를 따른다.
